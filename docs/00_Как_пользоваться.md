# Внешний протокол шлюза gate.atol.piot

Шлюз принимает **одну команду за запуск**. Команда — JSON-объект с одним ключом
верхнего уровня: **имя операции**. Всё внутри — параметры операции.

## Запуск

```
gate.atol.piot.exe --send <файл.json> [--no-dry-run] [--allow-fiscal]
```

| Ключ | Смысл |
|---|---|
| `--send <файл>` | выполнить команду из файла |
| `--dry-run` | **по умолчанию**: в кассу ничего не уходит, только собирается XML и пишется журнал |
| `--no-dry-run` | отправлять команды в кассу |
| `--allow-fiscal` | разрешить фискальные операции (чеки, закрытие смены) |

Хост компоненты поднимается отдельно (в будущей версии шлюз делает это сам):

```
gate.1c.addin.proxy.exe --http-port 8082 --http-bind 127.0.0.1 --dll fptr10_1c_win32_10_10_8_21.dll
```

## Как устроен полный дамп

В каждом файле, кроме запроса и ответа, приведён **полный обмен** — то, что шлюз
отправляет компоненте и получает от неё. Формат один и тот же:

```
→ {"jsonrpc":"2.0","id":101,"method":"Метод","params":[ … ]}
← {"jsonrpc":"2.0","id":101,"result":{ … }}
```

Дампы сняты с живой кассы АТОЛ (ФФД 1.2). Где помечено «форма вызова» — реальный
прогон этой операции не снимался, приведён точный вид обращения по коду шлюза.

## Где смотреть у себя

`logs\gate.atol.piot_ГГГГ-ММ-ДД.log`:

* `[НапечататьЧек] XML, который будет передан:` — собранный `CheckPackage`;
* `---> Метод: {…}` и `<--- Метод: {…}` — обмен с компонентой;
* `РЕЗУЛЬТАТ: {…}` — итог.
