# Проверить коды маркировки

**Операция:** `ПроверитьКодыМаркировки` · **методы:** `ЗапросКМ` → `ПолучитьРезультатыЗапросаКМ` → `ПодтвердитьКМ` · **флаги:** `--no-dry-run`

Одна команда выполняет весь цикл проверки КМ в Честном ЗНАКе.

## Запрос

```json
{"ПроверитьКодыМаркировки":{
  "ЭтоВозврат":false,
  "ТипПодтверждения":0,
  "КодыМаркировки":["0104690646123186215.cggydLlhI:h\u001d91EE12\u001d92GYkxObgqpwJwG2VMB1vvvEMkv59Y6s/XN203GRQ7E/0="]}}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `КодыМаркировки` | массив строк | да | коды **без** Base64, сырыми строками; разделитель GS1 — `\u001d`. В Base64 шлюз кодирует сам |
| `ЭтоВозврат` | логическое | нет | `true` — проверка для возврата |
| `ТипПодтверждения` | число | нет | `0` принять, `1` отклонить, отрицательное — не подтверждать. По умолчанию `0` |

## Ответ шлюза

```json
{"КодыМаркировки":{
  "0104690646123186215.cggydLlhI:h<GS>91EE12<GS>92GYkxObgqpwJwG2VMB1vvvEMkv59Y6s/XN203GRQ7E/0=":
  "проверка КМ пройдена (ОИСМ: Result=True, ResultCode=15, StatusInfo=1), КМ отклонена (тип 1)"}}
```

`<GS>` — невидимый разделитель 0x1D; в JSON он приходит как `\u001d`.

## Расшифровка ProcessingKMResult

| Атрибут | Смысл |
|---|---|
| `Result` | `True` — проверка КП КМ положительная |
| `ResultCode` | битовая маска, таблица 110 ФФД: бит 0 — код проверен, 1 — КП положительный, 2 — статус ОИСМ проверен, 3 — планируемый статус корректен. `15` = все четыре |
| `StatusInfo` | `1` — статус товара корректен |
| `HandleCode` | `0` — запрос обработан |
| `GUID` | нужен для отраслевого реквизита чека |

## Примечания

* `RequestKMResult Checking="False"` — норма для этой кассы: ФН не умеет проверять КП, итог даёт ОИСМ.
* Неподтверждённый запрос оставляет процедуру открытой: следующий `ЗапросКМ` падает с `401 «Процедура проверки КМ уже запущена»`. Снимается методом `ЗакрытьСессиюРегистрацииКМ`.
* Пока статус не `0` или `2`, другие операции с КМ невозможны.
