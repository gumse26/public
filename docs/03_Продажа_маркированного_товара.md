# Продажа маркированного товара

**Операция:** `НапечататьЧек` · **метод:** `СформироватьЧек` · **флаги:** `--no-dry-run --allow-fiscal`

Порядок: **1)** проверить КМ (`08_ПроверитьКодыМаркировки.md`, `ТипПодтверждения: 0`);
**2)** взять `GUID` из ответа проверки; **3)** отправить чек с кодом маркировки.

## Запрос

```json
{"НапечататьЧек":{
  "ТипЧека":"Продажа","СНО":1,"Кассир":{"Имя":"Администратор"},
  "Оплата":[1,0,0,0,0,0,0,0,0],
  "Товары":[{
    "Наименование":"Маркированный товар","Количество":1,"Цена":1,"Сумма":1,
    "Подразделение":0,"СтавкаНДС":"5","НомерНалога":"5",
    "ПризнакПредметаРасчета":33,"ПризнакСпособаРасчета":4,
    "КодМаркировки":"MDEwNDY5MDY0NjEyMzE4NjIxNS5jZ2d5ZExsaEk6aB05MUVFMTIdOTJHWWt4T2JncXB3SndHMlZNQjF2dnZFTWt2NTlZNnMvWE4yMDNHUlE3RS8wPQ==",
    "ОтраслевойРеквизитПредметаРасчета":{
      "ИдентификаторФОИВ":"030",
      "ДатаДокументаОснования":"30.09.2026",
      "НомерДокументаОснования":"1",
      "ЗначениеОтраслевогоРеквизита":"UUID={4923128C-1283-440A-9423-B8583B9D88C7}&Time=1790756821000"}}],
  "СуммаСкидкиНаЧек":0}}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `КодМаркировки` | строка | да | **полный** КМ в Base64, вместе с разделителями GS1 (0x1D) |
| `ПризнакПредметаРасчета` | число | да | для маркированного — `33` |
| `ИдентификаторФОИВ` | строка | нет | `030` — Честный ЗНАК (по умолчанию) |
| `ДатаДокументаОснования` | строка | нет | ДД.ММ.ГГГГ |
| `НомерДокументаОснования` | строка | нет | номер документа-основания |
| `ЗначениеОтраслевогоРеквизита` | строка | да | `UUID={GUID}&Time=<мс>` — **ККТ его не возвращает**, собирает вызывающая сторона |

## Примечания

* **Проверка КМ и чек обязаны идти через один и тот же хендл устройства.** Иначе ККТ отвечает `420 «Контрольная марка не проверена»`. В `config.json` хендл фиксируется полем `device`.
* `Time` методы проверки КМ не возвращают — берите метку времени сценария.
* Возврат маркированного товара — так же, но `ТипЧека: "Возврат"` и КМ проверяется заново с `ЭтоВозврат: true`.
